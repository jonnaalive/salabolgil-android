# 검증 범위

## 핵심 여정

1. 첫 실행에서 이사 후보지의 생활을 시험하는 목적과 시연 데이터 여부를 확인한다.
2. 내 생활 조건과 A/B 후보지, 병원 목적지·예상시간·출처를 설정한다.
3. A 병원 과제를 시작하고 주행 상태에서 상세 입력·비교가 차단되는지 확인한다.
4. 도착 알림만으로 이용 완료가 되지 않는지 확인한다.
5. 주차 후 실제 소요시간 18분과 이용 가능 여부를 저장한다.
6. 예상 12분 대비 +6분, 허용 15분 초과가 표시되는지 확인한다.
7. A/B의 같은 병원 항목이 나란히 나오고 B는 미확인으로 남는지 확인한다.
8. 사용자 확인으로 다음 과제로 이동하며 자동 완료나 자동 경로 전환이 없는지 확인한다.

## 상태와 복구

- 중복 도착 이벤트가 완료 기록을 만들거나 다음 과제로 넘어가지 않는다.
- 내비 요청 실패는 이동 성공으로 표시하지 않고 재시도 가능하다.
- 건너뛰기는 이용 가능·불가로 바꾸지 않는다.
- 앱 재시작 후 기록은 유지하되 안전한 주차 상태를 자동 복원하지 않는다.
- 실제 UX 상태를 알 수 없으면 상세 입력을 허용하지 않는다.
- 제한 해제는 안전한 주차의 증거로 취급하지 않는다.
- 기록 이후 예상값 변경이 과거 비교 결과를 조용히 바꾸지 않는다.
- 데이터 전체 삭제 후 이전 기록이 다시 나타나지 않는다.

## 실행 환경

순수 Java 상태엔진 테스트, APK 서명·릴리즈 빌드·Lint, 설치 후 실제 에뮬레이터 클릭 검증을 각각 기록한다. 에뮬레이터 확인을 실차 검증이라고 쓰지 않는다. 실제 내비 서비스와의 경로 요청 성공은 SDK 포함·앱 실행 성공과 별개로 기록한다.
